=================================
Control an actuator with Machine
=================================

This tutorial has one outcome: send a generated command to an Actuator through
a :class:`~crappy.blocks.Machine` and read its simulated motion.

Prerequisites
-------------

- Complete :doc:`command_generation` or know how to configure a Generator.

This example uses ``FakeDCMotor``. It requires no physical hardware, graphical
interface, or optional Python package. It creates no file and stops
automatically after four seconds.

The Generator alternates between positive and negative voltage commands. Its
``voltage(V)`` label matches the Machine's ``cmd_label``. The Machine drives
one ``FakeDCMotor`` in speed mode and publishes its simulated speed and
position under the labels given by ``speed_label`` and ``position_label``.
The LinkReader prints those values.

Run the simulated test
----------------------

From the directory containing the downloaded file, run:

.. code-block:: shell-session

   python actuator_control.py

The reported speed responds to each voltage change. A final
``Generator Path exhausted`` warning indicates the planned end of the test.
During normal cleanup, the Machine asks every Actuator to stop and close.

Use a real actuator
-------------------

.. warning::

   Do not run a modified script on connected machinery until you have checked
   the command units, allowed range, direction of motion, travel limits, and
   emergency-stop system. First test with the load disconnected or with the
   lowest safe command allowed by the equipment. Software cleanup does not
   replace independent physical safety systems.

To adapt the script:

1. Find the Actuator matching the controller on the :doc:`../features` page, or
   create your own Actuator object if no driver is distributed with Crappy.
2. Replace ``'FakeDCMotor'`` with that Actuator's name. Replace ``kv`` with the
   connection and configuration arguments listed in its API entry.
3. Select ``'speed'`` or ``'position'`` mode according to the operations that
   the Actuator supports.
4. Keep ``cmd_label`` identical to the label published by the command source.
5. Request ``speed_label`` or ``position_label`` only when the Actuator can
   read that value.

The meaning and safe range of a command depend on the selected Actuator. Verify
them in the equipment documentation before changing the values generated by
this example.
