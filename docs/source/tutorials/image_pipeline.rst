============================
Build a first image pipeline
============================

This tutorial has one outcome: acquire images with a CameraSource and display
them with an ImageDisplayer connected through an ImageLink.

Prerequisites
-------------

- Complete :doc:`quickstart` or be familiar with creating Blocks and Links.
- Install Matplotlib:

  .. code-block:: shell-session

     python -m pip install matplotlib

- Run the example from a graphical desktop where Python can open a window.

The example uses ``FakeCamera`` and does not access physical hardware. It opens
one image window, creates no file, and stops automatically after five seconds.
Its Camera configuration window is disabled, so no interaction is required
before acquisition begins.

Create the pipeline
-------------------

:download:`Download the complete script
</downloads/getting_started/image_pipeline.py>`, or create a file named
``image_pipeline.py`` containing this code:

.. literalinclude:: /downloads/getting_started/image_pipeline.py
   :language: python
   :start-after: # [image-pipeline-start]
   :end-before: # [image-pipeline-end]

``CameraSource`` owns the ``FakeCamera`` Camera object and publishes its
images. Because ``config=False`` disables interactive configuration, the
script gives CameraSource the image shape and data type in advance. The
``width`` and ``height`` settings passed to FakeCamera match that shape.

``ImageDisplayer`` is a separate VisionBlock. Its display rate can be lower
than the camera rate. :func:`crappy.img_link` connects the image output of
CameraSource to the displayer. The regular Link to ``stop`` lets the StopBlock
end the complete test after five seconds.

Run the pipeline
----------------

From the directory containing the downloaded file, run:

.. code-block:: shell-session

   python image_pipeline.py

The display window shows a moving grayscale pattern generated by FakeCamera.
A final ``Stop criterion reached`` warning indicates the planned end of this
example. The window and Camera object are then closed during normal cleanup.

Use a real camera
-----------------

To adapt the script:

1. Find the Camera object matching the device on the :doc:`../features` page
   or create your own Camera object if no driver is distributed with Crappy.
2. Replace ``'FakeCamera'`` with that Camera object's name and replace the
   FakeCamera settings with the connection and acquisition arguments required
   by the device.
3. Set ``config=True`` to preview images and adjust exposed settings before
   acquisition. Alternatively, keep ``config=False`` and provide the exact
   output ``img_shape`` and ``img_dtype`` along with the camera settings.

Check the manufacturer's connection, exposure, triggering, and operating
instructions before opening a physical camera. Note that the
:class:`Webcam camera <crappy.camera.Webcam>` allows reading images from most
webcams, and requires the ``opencv-python`` module to run.

Choose an image architecture
----------------------------

VisionBlocks are recommended for new image pipelines. The all-in-one Camera
Blocks remain supported and are not planned for deprecation. Read
:doc:`../concepts/image_pipelines` for the complete comparison and
:doc:`../concepts/regular_links_and_image_links` for the newest-frame delivery
behavior used by ImageLinks.

The `VisionBlock examples
<https://github.com/LaboratoireMecaniqueLille/crappy/tree/master/examples/vision_blocks>`_
show how to add recording, triggering, and image-processing stages.
